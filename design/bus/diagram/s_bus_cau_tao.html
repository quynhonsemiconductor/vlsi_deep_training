S_BUS được tạo từ những gì

Trả lời câu hỏi: có file top sẵn rồi làm tiếp, hay tự code? Cả hai: lõi là IP có sẵn, phần nối dây và cấu hình là tự viết. Wrapper chỉ gồm crossbar và cầu AXI2APB, không có router P_BUS.

1. Ba loại file

Mỗi file của S_BUS thuộc một trong ba loại. Biết loại file thì biết có được sửa hay không.

2. Bức tranh tổng thể

Nét liền đậm là file tự viết, nét đứt là file sinh ra, khung thường là IP có sẵn. Khung nét đứt dài bao quanh các khối là wrapper m_qnsc_wrap_bus. Router P_BUS (chia cổng APB ra các ngoại vi) không nằm trong wrapper này.

4. Cách ra được file wrapper

  1. Bạn sửa m_qnsc_wrap_bus.src.sv. Trong file có các comment đặc biệt như /*AUTOINST*/ (tự điền chân của instance) và /*AUTOINPUT*/, /*AUTOOUTPUT*/ (tự điền port lặp lại).
  2. Chạy make wrap trong design/bus/rtl/emacs/. Makefile gọi emacs verilog-mode mở rộng các comment đặc biệt đó.
  3. Kết quả ghi ra design/bus/rtl/m_qnsc_wrap_bus.sv. Chạy lại lần nữa phải ra đúng file giống hệt (không đổi gì).
  4. Lint và mô phỏng đọc bus.f, rồi build đúng file .sv này chứ không đọc file .src.sv.
Đừng sửa tay file m_qnsc_wrap_bus.sv. Lần make wrap sau sẽ ghi đè và mất thay đổi. Sửa ở .src.sv.

6. Dữ liệu đi qua như thế nào

Một lệnh đọc từ CPU đi như sau.

  1. Master đưa tín hiệu ra các port phẳng, ví dụ i_bus_axi_s_1_ar_addr.
  2. Lớp assign gộp các port phẳng thành struct request 183 bit.
  3. axi_xbar so địa chỉ với bảng 4 dòng để chọn slave. Địa chỉ không khớp dòng nào thì trả DECERR.
  4. Nếu đích là ROM, ISRAM hoặc DSRAM, struct 187 bit (ID rộng thêm 2 bit) được tách ra port phẳng và đi ra ngoài.
  5. Nếu đích là vùng ngoại vi 0x8000_0000, lệnh đi vào AXI2APB rồi ra cổng APB duy nhất của wrapper.
  6. Phản hồi đi ngược lại đúng đường đó.

7. Điều chưa chắc

Các thông tin trên mình đọc từ file hiện có, không dò lịch sử git để biết ai viết từng phần. Số dòng ở mục 5 là xấp xỉ, sẽ lệch khi file đổi.
